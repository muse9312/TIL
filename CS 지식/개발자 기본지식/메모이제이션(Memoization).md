# 메모이제이션(Memoization)
----

**같은 입력에 대한 계산 결과를 기억해뒀다가 재사용**하는 최적화 기법. 비싼 계산을 두 번 하지 않는다.

이름은 "memo(메모)"에서 왔다. memorization(암기)이 아니다.

```js
function memoize(fn) {
  const cache = new Map();
  return (...args) => {
    const key = JSON.stringify(args);
    if (cache.has(key)) return cache.get(key);   // 기억해둔 값
    const result = fn(...args);
    cache.set(key, result);
    return result;
  };
}
```

## 전제 조건 — 순수 함수여야 한다

메모이제이션이 성립하려면 **같은 입력 → 항상 같은 출력**이어야 한다.

* 외부 상태를 읽거나 바꾸는 함수
* `Date.now()`, `Math.random()` 을 쓰는 함수
* 네트워크·파일 I/O를 하는 함수

이런 건 캐시하면 **틀린 값을 반환**한다. 순수하지 않은 함수를 메모이제이션하는 건 최적화가 아니라 버그다.

## React에서의 메모이제이션

React는 상태가 바뀌면 컴포넌트를 다시 실행한다. 그 과정에서 불필요한 재계산·재렌더가 생기는데, 이를 막는 도구가 셋이다.

| 도구 | 기억하는 것 | 쓰는 경우 |
| ----------- | ----------- | ----------- |
| `useMemo` | **계산 결과값** | 무거운 연산, 참조 동일성이 필요한 객체/배열 |
| `useCallback` | **함수 자체** | 자식에게 콜백을 내려줄 때 |
| `React.memo` | **렌더 결과** | props가 안 바뀌면 자식 렌더를 건너뜀 |

```jsx
// 참조가 매번 새로 생기면 자식이 계속 리렌더된다
const filtered = useMemo(
  () => items.filter(i => i.level === level),
  [items, level]
);

const handleClick = useCallback((id) => select(id), [select]);
```

### 핵심은 "참조 동일성"
JS에서 `{} !== {}` 다. 렌더할 때마다 새 객체·새 함수가 만들어지면, 값이 같아도 **참조가 달라서** 자식이 리렌더된다. `useMemo`/`useCallback` 은 주로 이 참조를 고정하려고 쓴다.

### 장점
* 불필요한 재계산·재렌더 제거
* 실시간 데이터처럼 **갱신이 잦은 화면**에서 효과가 큼

### 단점
* **공짜가 아니다** — 캐시 저장과 의존성 배열 비교에도 비용이 든다. 가벼운 계산을 감싸면 오히려 손해
* **의존성 배열 관리가 실수의 온상** — 빠뜨리면 낡은 값(stale closure)을 붙잡고, 과하게 넣으면 매번 무효화돼 의미가 없어짐
* 코드가 지저분해진다. 로직보다 최적화 코드가 눈에 먼저 들어옴

## 그래서 자동화가 나왔다

위 단점 — 특히 **사람이 일일이 붙여야 하고 실수하기 쉽다**는 점 — 때문에 [[React Compiler]] 가 등장했다. 빌드 타임에 컴파일러가 알아서 메모이제이션을 삽입해준다.

## 언제 손으로 붙일까

1. **먼저 측정한다.** React DevTools Profiler로 실제 병목을 확인
2. 리렌더가 **눈에 보이는 느려짐**을 만들 때만
3. 참조 동일성이 **논리적으로 필요할 때** (의존성 배열에 들어가는 값 등)는 성능과 무관하게 필요

> 추측으로 붙이지 말 것. 대부분의 리렌더는 문제가 아니고, 진짜 병목은 [[상태 관리]] 구조(구독 범위를 얼마나 좁혔는가)에서 온다.
